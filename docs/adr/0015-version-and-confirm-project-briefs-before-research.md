# Version and confirm project briefs before research

Research Projects retain the original natural-language request and organize it into immutable Project Brief versions. The intake asks only for missing change event, target audience, or communication goal because those gaps materially alter the research scope.

Each answer or manual edit creates a new Brief version. Confirmations point to a specific version, and any later edit returns the project to draft status. Discovery and collection may start only when the current Brief has been explicitly confirmed.

The web workspace and `mediahunter` Skill use the same project service and API. This keeps project evidence and conclusions isolated while shared content remains in MediaHunter's common content store.
